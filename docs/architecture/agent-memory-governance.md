# Agent Memory Governance

## Purpose

Agent memory is a governed data store, not an unrestricted extension of the model. Session state and persistent memory have different lifetimes, owners, purposes, and deletion requirements and must be represented separately.

## Memory classes

| Class | Example | Default lifecycle |
|---|---|---|
| Session state | Current task context | Expires with session or configured short TTL |
| User preference | Explicitly saved response preference | User-controlled purpose and retention |
| Work/project memory | Approved project decisions and status | Project owner, access policy, and review date |
| Source-derived fact | Extracted fact from an approved document | Inherits source lineage and revocation |
| Agent inference | Hypothesis or generated summary | Clearly labeled as inference; never represented as verified source fact |

## Required memory metadata

Each persistent memory record should include:
- memory ID, tenant ID, owner/subject, and permitted readers;
- memory class and purpose;
- content classification;
- created, updated, last-reviewed, and expiry timestamps;
- retention policy ID and deletion status;
- source IDs and source versions;
- derivation method/model version where relevant;
- confidence or quality label where appropriate;
- authorization policy version and audit correlation.

## Read and write controls

Every memory read, write, update, summary, export, and deletion must validate the current SecurityContext and evaluate policy for the specific memory resource and purpose. Memory ownership does not automatically imply permission to read every source-derived memory if source permissions have changed.

## Provenance and epistemic labels

Use explicit labels such as:
- `source-backed`: directly supported by one or more identified sources;
- `derived`: synthesized from identified source records;
- `user-provided`: explicitly supplied by a user;
- `inferred`: generated by the model and not independently verified.

A memory's label must not be upgraded merely because it is repeated or retrieved often. Answers should distinguish source evidence from inference.

## Revocation and deletion

When source access is revoked or a source is deleted, dependent memories are denied immediately and then invalidated or deleted through the lifecycle cascade. User or tenant deletion must cover replicas, indexes, summaries, caches, and backups according to approved retention and legal-hold policy. Deletion completion must be evidenced, not assumed.

## Human and institutional authority

Agents cannot unilaterally decide what becomes persistent memory, extend retention, override deletion, or grant access. Memory policies and any exceptions are owned by designated human/institutional authorities. Sensitive or high-impact memory classes require explicit approval and stronger controls.

## Evaluation

Test owner isolation, tenant isolation, purpose limitation, expiry, source revocation, deletion propagation, provenance completeness, inference labeling, and resistance to prompt-injection attempts to write malicious or unauthorized memories.
